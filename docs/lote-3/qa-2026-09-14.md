  descuido de este lote (es una decisión de seguridad ya tomada y documentada), pero el
  riesgo operativo que señaló el coordinador es real y vigente: cualquier `migrate:fresh`
  (con o sin `--seed`) deja el CMS sin ningún usuario con `is_admin=1`, y hoy el único
  camino de recuperación es crear uno a mano por tinker/SQL — exactamente lo que pasó
  anoche. Lo reporto como hallazgo de proceso para quien planifique el próximo
  `migrate:fresh` en un entorno compartido, no como defecto de código de este lote.
